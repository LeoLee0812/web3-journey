> **一句话结论：** 智能合约就是一个自动售货机——接收交易（投币），检查条件（商品库存），执行逻辑（出货），改写状态（库存减少），但它永远无法主动向外界说"买我的商品"。

## 为什么要讲这个

![街边一排自动售货机](/images/05-ethereum-smart-contracts/03-what-is-contract.jpg)

*图注：智能合约就像这些售货机——不投币就不会出货，永远被动等待指令 · 图片：Pexels / Huu Huynh*

你可能听过"智能合约自动执行"、"无需信任"这样的说法，但这些词很容易让人想象错误。很多人以为智能合约是一个主动的、会自己做决策的"智能助手"，其实恰恰相反——合约是完全被动的。

想象你在便利店买水。店员的流程是：看到你拿起水瓶 → 扫描商品码 → 检查库存 → 收钱 → 给你结账收据。这是**有感知、会主动响应**的行为。但自动售货机呢？它只能等你投币，然后机械地执行预设的程序。如果没有人按按钮，它就一动不动。

以太坊上的智能合约正是这个原理。没有"聪明"可言，它的"智能"不过是代码的自动执行和不可篡改。理解这一点，你才能真正把握合约能做什么、不能做什么。

## 核心机制拆解

### 三大构成与被动本质

一个完整的智能合约包含三个不可分割的部分：

| 构成部分 | 实际内容 | 作用 |
|---------|--------|------|
| **代码** | Solidity编写，编译为EVM字节码 | 决定执行逻辑（怎么做） |
| **存储** | 链上持久化的键值对数据库 | 记录当前状态（有什么） |
| **余额** | 该合约名下的ETH，以wei计（1 ETH = 10^18 wei） | 合约自身资产（1 wei是最小单位） |

代码规定兑换规则，存储记录用户账户余额，余额存着合约赚到的手续费。这三部分缺一不可。

合约本身**没有时钟、没有眼睛、没有意志**。它不会主动检查价格、不会自动触发行为、也无法发起网络请求。合约**只能被调用**——必须有人（或机器人）发送交易，合约才会执行：

### 从投币到出货

当你在钱包点击"发送"时，实际上是向EVM说："执行合约X上的函数Y"。EVM的执行流程是确定性的：

1. **验证签名**：确保你的私钥签过这笔交易
2. **预扣Gas费**：计算会消耗多少计算资源
3. **执行字节码**：逐条运行合约指令
4. **改写存储**：修改账户余额、代币数量等状态
5. **产生收据**：记录Gas消耗和发生的事件

整个过程**确定性、透明、不可逆**。无论谁执行，结果都相同——这就是"智能"的含义，不需要第三方背书。

### 部署即永久写入

你编译好的Solidity代码要部署到链上。部署就是发送一笔特殊交易，数据字段填入字节码和初始参数。EVM执行时：

1. 运行构造函数（`constructor`），初始化状态变量
2. 计算合约地址（由部署者地址和nonce组合生成，或CREATE2哈希）
3. 永久存储代码到这个地址上

**一旦部署，代码就无法改变**（除非用代理模式）。这就是为什么合约审计极其重要——一行代码的漏洞可能伴随合约一生。

## 🧪 真实案例：The DAO 重入漏洞

2016年6月，以太坊最大众筹项目The DAO被黑客利用**重入漏洞**盗走360万个ETH。黑客的手段很巧妙：

合约代码是"检查余额 → 转账 → 更新余额"。但在转账那一刻，黑客触发合约的回调函数（`fallback`），在余额还没被更新前再次进入合约，重复提取。售货机程序有漏洞，就出货了不该出的商品。

修复其实很简单——改为"检查余额 → 更新余额 → 转账"，这样黑客再进来时余额已是零。但**合约无法改**，只能整个以太坊硬分叉回滚，引发巨大争议并分裂出Ethereum Classic。这完美说明了代码即法律的无情和合约的永久性。

## ⚠️ 常见坑与误区

1. **自动执行≠主动执行**  
   合约永远被动，没人调它就永远睡觉。必须有机器人或预言机定时发送交易才能触发。

2. **"智能"这个词易误导**  
   合约不会学习、不会优化、不会自适应。唯一的优势是代码自动执行和完全透明。

3. **交易回滚仍要付Gas费**  
   执行过程中如果条件不满足（余额不足等），整个交易回滚如同未发生。但你已被扣Gas费（计算资源消耗是真实的）。

4. **代码一旦部署就永久写死**  
   任何bug都无法修复，除非当初设计了升级机制。这是不可篡改的代价。

5. **数据都是公开可读的**  
   标记为`private`的状态变量只是编译层限制，无法真正隐藏数据——所有内容都在区块链上。

## 本节要点

- 智能合约 = 自动售货机，被动响应、按程序执行、永不主动
- 由代码（逻辑）、存储（状态）、余额（资产）三部分组成
- 交易触发执行流程：验证签名 → 扣Gas → 运行代码 → 改写状态 → 记录区块
- 部署后代码永久写入，无法修改（除非事先设计升级机制）
- 安全性完全取决于代码严谨性，一行漏洞可能伴随合约终身

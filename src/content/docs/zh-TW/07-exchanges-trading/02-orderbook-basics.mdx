> **一句話結論：** 訂單簿不是神秘的黑盒，它只是等待成交的買單與賣單的排隊，滑點設定高低直接決定你是否會被夾取，學會看這張圖就能理解交易介面背後的所有數字。

## 從交易介面說起

你在 Uniswap 交換 1000 USDC 換 ETH，看到紅色警告："Transaction is expected to fail"。調整引數半天都不行，但另一個幣突然成功了。這不是 bug，這是**滑點**在捉弄你。

每筆交易背後，你的單並非立刻成交，而是進入公開交易池等待撮合，根據你能接受的最差價格（滑點容限）決定成交還是失敗。這個過程的核心就是**訂單簿**（Order Book）。即使 DEX 用自動做市商（AMM）替代了傳統訂單簿，滑點和流動性深度的原理依然相同。

## 核心機制拆解

### 訂單簿的兩側：買方與賣方

想像一個咖啡館，左邊是想買咖啡的人，右邊是想賣咖啡的人。他們不是直接碰面，而是通過一個價格列表來配對。

在交易所中：

- **Buy Side（買方）**：已經下單等待購買的人，按價格從高到低排列。最高出價的買單在最上面。
- **Sell Side（賣方）**：已經下單等待出售的人，按價格從低到高排列。最低要價的賣單在最上面。

交易什麼時候成交？當買方願意接受賣方的價格（或反之）時。最上面的買單價格與最上面的賣單價格之間的差值，就叫做**點差（Spread）**。

例如：

| 買方的價 | 數量 | | | 賣方的價 | 數量 |
|---------|------|---|---|---------|------|
| 2000 | 5 ETH | | | 2005 | 2 ETH |
| 1999 | 8 ETH | | | 2006 | 3 ETH |
| 1998 | 10 ETH | | | 2007 | 4 ETH |

最高買價是 2000，最低賣價是 2005，**點差 = 5 美元**。點差越小，流動性越好；點差越大，說明這個交易對交投者不多。

### 流動性深度：大額交易的價格衝擊

"深度"衡量某個價格範圍內的累計訂單量。在上例中，你想一次買 5 個 ETH，可按最低賣價 2005 全部成交。但買 10 個 ETH，前 2 個按 2005 成交，剩餘 8 個要按 2006 價格接受，平均成本變高了。交易所常寫"$100K depth"或"$1M depth"，表示該交易對在±2% 價格範圍內的累計訂單總量。深度越大，大額交易對價格衝擊越小。

### 滑點：你的預期價與實際成交價的差距

**滑點（Slippage）** = 預期成交價格 - 實際成交價格（百分比表示）。

你看到 1 ETH = 2000 USDC，點選交換，結果成交時價格已經變成 1 ETH = 1990 USDC。滑點 = 0.5%。

為什麼會發生？三個原因：

1. **市場波動**：你點選到成交的那幾秒鐘，市場價格在動
2. **大額訂單衝擊**：你的訂單很大，吃掉了訂單簿的多層報價
3. **MEV 機器人夾取**：在你前面或後面插入交易來獲利（更復雜的問題，下文解釋）

### 滑點容限：你願意被坑多少

錢包和交易所的"滑點容限"設定，其實是這樣定義的：

```text
最小接收額 = 預期輸出 × (1 - 滑點容限)
```

例：預期得到 10 ETH，滑點容限設 2%，最小接收額 = 10 × (1 - 2%) = 9.8 ETH。如果實際成交少於 9.8 ETH，交易自動失敗回滾。

關鍵洞察：**低滑點 = 向市場宣告"我不願意被坑超過 X%"，機器人如果利潤空間小於這個閾值，就會忽視你的訂單**。這是防 MEV 的第一防線。

根據 2026 年實操資料，滑點容限應該怎麼設？

| 幣種與流動性等級 | 推薦滑點容限 | 場景 |
|---|---|---|
| **藍籌代幣**（ETH、BTC、SOL 等深流動性對） | 0.1–0.5% | 日常交換，交投最活躍 |
| **中等市值幣**（$10M–$100M TVL） | 0.5–1% | 較小的交易所或小幣種 |
| **小市值幣**（$100K–$10M TVL） | 1–3% | 流動性稀缺 |
| **迷因幣 / 超小市值**（&lt;$100K TVL） | 5–15% | 流動性極少，風險很高 |
| **有稅的代幣** | 基礎滑點 + 稅率 | 代幣本身費用需加入 |

## 🧪 真實案例：為什麼 $220,000 變成了 $5,272

2026 年，一位交易者在 Uniswap V3 上將 $220,800 的 USDC 換成 USDT。點選交換時預期獲得約 $220,000 USDT，但實際成交時只收到 $5,272 USDT——**損失 99.76%**。

發生了什麼？**三明治攻擊**（MEV 夾取）：

1. MEV 機器人看到你的大額交易在記憶體池中等待（還未確認上鍊）
2. 機器人先發起一筆交易，買入 USDT、抬高其價格
3. 你的交易接著執行，因價格已被抬高，你只能以更差的匯率成交
4. 機器人最後發起平倉交易，賣出 USDT 獲利

最終，機器人從這筆交易中獲利約 $8,000，而你損失了 $215,000。

**這個案例的根源**：使用者沒有設定足夠低的滑點容限。如果設定 0.1% 滑點限制，這筆壞交易會被自動拒絕，保護了資產。

## ⚠️ 常見坑與誤區

1. **滑點設定過低導致交易反覆失敗**：新手看到"Transaction is expected to fail"就頻繁提高滑點。正確做法是根據流動性調整，先小額測試。如果設 0.5% 都失敗，說明流動性太差，應考慮放棄而非繼續加滑點。

2. **誤認為高滑點 = 更安全的成交**：高滑點確實提高成交機率，但也宣告了你能接受被夾取 5%–15%，這是 MEV 機器人的"盛情邀請"。低滑點反而能有效阻止機器人，因為利潤空間消失了。

3. **忽視代幣稅費**：某些代幣在轉帳時收稅（如早期的 Safemoon），這是額外的隱性滑點，需要加到容限裡。提前查合約程式碼檢查代幣是否有稅。

4. **大額交易一次性下單**：$1,000 交換可能 0.1% 滑點，同一幣對 $100,000 交換可能需要 2% 滑點。滑點同時受市場波動和訂單大小影響，分批交易能顯著降低風險。

## 本節要點

- 訂單簿的買賣掛單排隊，點差是最高買價與最低賣價的差值
- 流動性深度越大，大額交易對價格衝擊越小
- 滑點由市場波動和訂單大小共同決定
- 低滑點容限是防 MEV 的第一防線，機器人利潤空間消失時會忽視你的訂單
- 根據流動性調整滑點：藍籌 0.1–0.5%，小幣 1–3%
- 大額交易被夾成 99.76% 損失的真實風險，可通過分批交易和私有 RPC 防護

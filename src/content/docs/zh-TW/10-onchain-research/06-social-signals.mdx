> **一句話結論：** 社群熱度可以量化追蹤，但高熱度≠專案好，關鍵是區分真實活動與炒作訊號，用開發者活躍度和鏈上指標雙驗證。

## 為什麼看社群熱度會上當

想像你在研究一個開源專案。如果你只看 GitHub star 數，可能被迷惑；但如果翻開提交歷史，發現最後一次更新是 3 個月前，那就知道這個專案其實已經沒人維護了。Web3 專案也一樣。

許多專案有龐大的 Discord 社群（數字可能通過 bot 水軍虛高）、鋪天蓋地的 Twitter 發言（可能是營銷團隊的日常轉發），但開發者可能只有 3 個人，上週一行程式碼都沒提交。這時候，**熱度指標和實際活躍度完全脫節**。

2026 年 DeFi 失敗專案中，不少在融資時有超過 5 萬 Discord 成員和高度的社交熱度，結果產品遲遲沒有迭代，最後逐漸失去使用者。所以你需要學會用多維指標來量化社群熱度，而不是被單一的數字迷惑。

## 社交訊號的四維量化框架

社群熱度不是一個數字，而是四個獨立維度的組合：

**維度 1：規模指標**  
直接可見的資料——Discord 成員數、Twitter 粉絲數、GitHub stars。2026 年活躍的加密 Discord 伺服器超過 6.7M 個，但大多數是殭屍成員。規模本身說明不了問題，但用來追蹤**周環比增長**才有意義。如果一個專案 Discord 一週增長 5%，連續 4 周都是 5%，說明有穩定的新使用者進來；如果一次增長 50%，然後跌回來，可能是某次營銷活動造成的虛假繁榮。

**維度 2：互動頻率**  
Discord 日活躍使用者佔成員總數的比例、Twitter 平均轉發數、媒體提及頻率。一個 5000 人的 Discord，如果每天只有 20 個人聊天，那實際活躍度遠低於表面。Learn2Trade、Token Metrics 等 AI 訊號提供商正是通過追蹤**討論頻率的變化**來發現風險訊號。

**維度 3：內容質量**  
討論的深度——是技術討論、產品反饋，還是空喊"To the moon"？高質量社群會有使用者問具體問題（"這個合約的風險是什麼""代幣解鎖時間表什麼時候"），而低質量社群只有情緒宣洩。這個維度最難量化，但可以通過**取樣** 10 條最新討論來快速判斷。

**維度 4：增長趨勢**  
這個月的活躍度 vs 上個月 vs 去年。專案早期增長是正常的，但如果連續 3 個月活躍度下降超過 20%，那就該警惕了。

## 開發者活躍度：真實專案的晴雨表

開發者活躍度遠比社交熱度可靠。為什麼？因為**程式碼不會說謊**。

- **GitHub commits 頻率**：平均每週提交數。一個認真維護的專案，至少每週應該有 5-10 次提交。如果連續 2 周零提交，說明要麼凍結了，要麼團隊換人了。
- **Issue 響應時間**：使用者提 bug，團隊多久回覆？48 小時內回覆是及格線，24 小時內是優秀。如果 Issue 堆積超過 20 個，說明維護能力跟不上了。
- **PR merge 速度**：待稽核的拉取請求數。如果有 30 個 PR 等待合併，說明 code review 的瓶頸嚴重。
- **程式碼變化量**：不只看提交數，還要看每次提交的程式碼行數。一週 50 次提交但每次只改 1 行，不如 5 次提交每次 100 行。

你可以在 Dune Analytics 上檢視這些資料（需要自建查詢連線 GitHub API），或直接在 GitHub 專案頁用"Insights"標籤看統計。更簡單的方法是用 web3data.com 的 Developer Dashboard，它已經把這些指標聚合好了。

## 量化可靠性排序

並非所有訊號的可靠性相同。這是一個金字塔：

| 訊號等級 | 內容 | 可造假成本 | 使用建議 |
|--------|------|---------|--------|
| **1 級（最可靠）** | 鏈上活動、Gas 消耗、交易量 | 極高（需真實資產） | 當做判斷基準 |
| **2 級** | GitHub commits、審計歷史、升級頻率 | 高（需技術+時間） | 驗證專案認真度 |
| **3 級** | 日活錢包數、重複使用者比例 | 中高（需資料技能） | 交叉參考 |
| **4 級** | Twitter/Discord 熱度、KOL 轉發 | 低（容易買量） | 僅作參考 |
| **5 級（最不可靠）** | 新聞稿、融資公告、品牌合作 | 極低（純營銷） | 需要獨立驗證 |

為什麼這樣排序？造假成本遞增。買 1 萬個 Twitter 殭屍粉成本低；製造虛假 GitHub 貢獻需要更多技術；偽造鏈上活動需要真實的加密資產和風險。

## 🧪 實戰：用 3 層驗證法評估專案

<Steps>

1. **第一層：社交快速掃描**（5 分鐘）
   - 開啟專案的 Discord，看"活動"頻道過去 24 小時有多少條訊息（右鍵點選頻道→"View Details"）
   - 翻 Twitter 過去 1 周的發文，看官方帳號更新頻率（日更、周更還是月更？）
   - 記錄：規模數字 + 周環比增長率

2. **第二層：開發者活躍度核實**（10 分鐘）
   - 進專案 GitHub 主倉庫，點"Insights"→"Commits"，看過去 3 個月的提交趨勢
   - 開啟最近 20 個 Issue，看平均響應時間（從 Issue 發起到第一條回覆的時間）
   - 計算：周平均提交數，Issue 響應時間中位數

3. **第三層：鏈上資料驗證**（15 分鐘）
   - 上 Dune Analytics 搜專案名，找一個公開的生態看板
   - 看"日活使用者數"（DAU）過去 3 個月的趨勢，對比"社交熱度"是否同步增長
   - 如果社交熱度↑但 DAU→，說明熱度虛假；如果 DAU↑但社交冷淡，說明專案在悶聲做事

4. **綜合判斷**
   - 將三層資料整理成一份簡表
   - 找矛盾點：哪一層資料與其他層不符？那就是風險訊號

</Steps>

## ⚠️ 常見坑與誤區

**坑 1：Twitter/Discord 粉絲數可以買**  
機器人帳號成本極低。單純看粉絲數的增速是一個陷阱。應該看**真實互動率**：總轉發數 / 粉絲數。如果 10 萬粉絲卻平均只有 100 個轉發，說明粉絲質量很差。

**坑 2：GitHub commits 可以刷**  
新手常被"日均 50 次提交"迷惑。但如果你看程式碼改動（diff），會發現是在不同檔案裡改空格、重複提交等無用操作。應該看**程式碼實際變化量**而非提交數。

**坑 3：混淆相關性與因果關係**  
"Discord 活躍度高，然後價格漲了"不代表熱度導致上漲，也可能是**價格先漲**吸引新使用者進 Discord。因果方向的辨析方法詳見[本章第 3 節](/zh-TW/10-onchain-research/03-data-platforms/)。

**坑 4：忽視社群討論的質量**  
兩個專案都有 5000 個 Discord 成員。A 專案討論都是技術問題和風險提示，B 專案只有情緒宣洩和"HODL"。A 的風險**可能更低**，因為社群在做真正的盡職調查。

**坑 5：單一指標決策**  
如果你看到"開發者很活躍"就下結論專案安心，那就錯了。即使程式碼提交頻繁，也可能改的是無關緊要的東西。需要**跨維度驗證**。

## 本節要點

- 社群熱度的四維量化框架：規模、互動頻率、內容質量、增長趨勢；每個維度權重不同
- 開發者活躍度指標（commits、Issue 響應時間、PR merge 速度）比社交熱度可靠 5-10 倍
- 訊號可靠性有金字塔排序：鏈上活動 > 開發者 > 使用者增長 > 社交 > 營銷宣傳
- 用 3 層驗證法（社交掃描→開發檢查→鏈上驗證）找出虛假熱度的破綻
- 高社交熱度≠專案好；熱度與 DAU、程式碼活躍度**不同步**是最大的風險訊號
- 避免被單一指標迷惑，始終尋找多維資料之間的矛盾

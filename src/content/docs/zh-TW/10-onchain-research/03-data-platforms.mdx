> **一句話結論：** 沒有"最好的"資料平臺，只有最適合當前問題的工具——TVL 用 DefiLlama，自定義分析用 Dune，追蹤巨鯨用 Nansen/Arkham，選對工具才能少走彎路。

## 從一個真實場景說起

你發現了一個新的 DeFi 借貸專案，官網說 TVL 已經 3 億美元。這聽起來很有規模，但你想知道：這筆錢真的在協議裡嗎？是來自哪些錢包？有沒有大額抽離跡象？是不是被少數幾個鯨魚壟斷？如果你拿著這些問題去同一個平臺查，可能永遠得不到答案。

**原因很簡單：鏈上資料工具是專用的，不是萬能的。** 有的擅長看全景（TVL 排行），有的擅長看細節（單筆轉帳），有的擅長追蹤特定物件（巨鯨異動），有的擅長深層分析（自定義 SQL 查詢）。把一個為"看全景"設計的工具用來"追蹤細節"，你會浪費時間，甚至得出錯誤結論。

## 四類平臺各有絕活

### 1. 全鏈聚合 & TVL 看板：DefiLlama

**解決的問題：** "某條鏈上有多少錢？某個協議有多大規模？"

**核心特性：**
- 覆蓋 48+ 條區塊鏈（從以太坊、L2、到 Solana、Cosmos 等）
- 聚合所有主流 DeFi 協議的鎖定資產總額（TVL）
- 不需要程式碼基礎，點兩下滑鼠就能看排行

**關鍵資料（2026 年 6 月）：**
- 全鏈總 TVL：$74.085 billion
- 以太坊佔比：53.1%（Ethereum 本身 TVL $38.24b）
- 單個協議最大：Lido 達 $17.533 billion

**什麼時候用？**
當你需要快速瞭解生態規模和發展趨勢時。比如："Base 鏈上的 TVL 最近在長還是在跌？DeFi 整個賽道今年損失了多少？"

**坑點：** TVL 只是表面數字，不代表專案健康度。2026 年初至今全鏈 TVL 下跌了 37.3%，但這不代表每個協議都在衰退——很多是流動性重新分配。

### 2. 自定義查詢 & SQL 分析：Dune Analytics

**解決的問題：** "我想要一個沒人做過的分析，需要跨鏈比對資料，或者追蹤某個特定時間段的交易。"

**核心特性：**
- 基於 Trino 的 SQL 引擎，支援 130+ 個區塊鏈
- 社群已貢獻 200K+ 公開儀表板，1.5M+ 資料集
- 新手可直接 Fork 別人的查詢改引數，無需從零開始寫 SQL

**為什麼 Dune 改變了研究方式：**
在 Dune 之前，鏈上研究需要自己跑全節點或寫爬蟲。Dune 把這個成本從"幾個月"降到"幾分鐘"。你不僅能看預製的儀表板，還能立即複製、修改、擴充套件——比如"看遍歷歷史上所有 Aave 的 liquidation"或"對比 Base 和 Arbitrum 的新使用者留存率"。

**最常見的查詢場景：**
- ERC-20 轉帳追蹤（某代幣在 7 天內從誰流向誰）
- DEX 交易分析（Uniswap 在某條鏈上的日交易量）
- 錢包餘額聚合（某地址在 N 個協議上的所有資產）

**坑點：** 公開儀表板的資料可能滯後或缺乏更新。一定要檢查"Last Updated"時間戳。同時，用 SQL 查詢一整條鏈的歷史資料時，也別貪大——容易超時。

### 3. 聰明錢追蹤 & 地址標籤：Nansen / Arkham

**解決的問題：** "這筆大額轉帳來自誰？是真的專案方還是釣魚地址？某個巨鯨最近在做什麼？"

**兩個主流選項的對比：**

| 工具 | 主要強項 | 資料模式 | 價格 |
|------|--------|--------|-----|
| **Nansen** | Smart Money 行為識別，即時追蹤聰明投資者 | 訂閱制 SaaS | $25K+/年（企業方案） |
| **Arkham** | AI 驅動的地址去匿名化，眾籌標記系統 | 代幣經濟 + 免費基礎版 | 免費查詢 + ARKM 代幣解鎖高階功能 |

**為什麼這兩個工具改變了鏈上追蹤：**
在 2023 年之前，想要知道一個錢包屬於誰，基本靠猜。現在 Nansen 和 Arkham 通過人工和機器學習，已經為數百萬個地址做了分類標籤——"幣安冷錢包""FTX 創始人錢包""Lido 流動性質押池"等等。這讓"聰明錢追蹤"從定性變成定量。

**什麼時候用？**
- 看到大額異動想知道對手方身份
- 追蹤特定投資方（比如某個知名 VC）最近的動向
- 評估某個專案的資金集中度（由多少個大戶壟斷）

**坑點：** 標籤系統有 50% 以上的誤報率，特別是遇到 CoinJoin 混幣或虛假冒充。**永遠不要單獨依賴一個平臺的標記**——最安全的做法是"跨平臺交叉驗證"（Etherscan + Arkham + 手工檢查）。

### 4. 社交與開發者訊號：Discord / GitHub / Twitter

**解決的問題：** "這個專案的社群活躍嗎？開發者在認真做還是放棄了？"

**資料來源和口徑（2026 年）：**
- **Discord**：全球加密伺服器 6.7M+ 活躍，每個專案的 Discord 成員數可以反映基層熱度
- **GitHub**：提交頻率、Issue 響應時間、PR 合併率是更難偽造的指標
- **Twitter/X**：AI 訊號提供商（如 Learn2Trade、Token Metrics）可即時監聽專案動向

**為什麼社交指標容易被欺騙：**
- Discord 和 Twitter 粉絲都能用機器人購買
- GitHub commit 可以通過瑣碎改動人為增加
- 牛市時所有專案的熱度都飆升，熊市時都腰斬——**需要用市場週期做背景對比**

**可信度排序（從高到低）：**
1. 實際交易成本（Gas 消耗量）—— 最難偽造
2. 獨特活躍錢包數 —— 難偽造但可用冷錢包規避
3. GitHub commit 和 Issue 響應 —— 有人工成本，但能偽造
4. Discord 和 Twitter 熱度 —— 最容易偽造

## 🧪 實戰：用這些工具研究一個真實專案

假設你要評估"某個新借貸協議"。以下是標準的資料收集流程：

<Steps>

1. **第一步：用 DefiLlama 看規模和趨勢**
   - 進入 DefiLlama，搜尋專案名
   - 記下 TVL、排名、30 天趨勢（上升還是下跌？）
   - 如果 TVL 在過去一個月內下跌 >50%，需要特別關注風險

2. **第二步：用 Arkham 或 Etherscan 看資金集中度**
   - 複製專案的合約地址
   - 在 Arkham 上檢視"Largest Holders"
   - 檢查：是否有單個錢包持有超過 30% 的資金？如果是，存在風險集中

3. **第三步：用 Dune 做深層分析**
   - 搜尋社群公開儀表板（例如"Aave Flow Analysis"）
   - Fork 一個類似專案的儀表板，修改合約地址
   - 比對：新使用者流入 vs 老使用者流出的比例

4. **第四步：用 Nansen 追蹤"聰明錢"動向**
   - 看過去 7 天是否有已標記的 "Smart Money" 進場或撤出
   - 如果大量聰明錢在撤，這是明確的風險訊號

5. **第五步：檢查社交和開發訊號**
   - GitHub：最近一週有多少 commit？Issue 響應時間？
   - Discord：成員數，活躍度，是否都是買來的機器人？（看聊天質量）

</Steps>

**整個流程用時 15-30 分鐘，但能回答"這個專案真的有規模還是虛高"這個核心問題。**

## ⚠️ 常見坑與誤區

1. **過度反應單筆大額交易** —— 看到巨鯨轉帳就認為"鯨魚在積累"或"價格要漲"，實際上單筆交易可能是技術操作或虛假訊號。巨鯨訊號的完整解讀方法詳見[本章第 5 節](/zh-TW/10-onchain-research/05-whale-tracking/)。

2. **忽視倖存者偏差** —— 用 Dune 歷史資料計算"過去 5 年成功代幣的平均收益"，以為這代表投資勝率。但已死亡、rug-pulled 的代幣已從資料庫消失。真實成功率遠低於統計顯示。

3. **混淆相關性與因果關係** —— 看到"巨鯨買入 3 天后價格漲了 15%"就斷定"巨鯨推高價格"。可能真實原因是市場情緒轉變，或者價格上漲反過來吸引了巨鯨。鏈上指標適合"發現訊號"，不適合"證明因果"。

4. **完全依賴自動聚類標記** —— 某個"幣安冷錢包"的標記可能是冒充者；某個被標記為"洗錢錢包"的地址其實是正常使用者。務必跨平臺驗證（Etherscan + Arkham + 手工檢查）。

5. **不區分"美元價值"與"代幣數量"** —— 匯率浮動會讓同樣的美元金額對應不同的代幣數量，追蹤大額轉移時應優先用代幣數而非 USD 標價，詳見[本章第 5 節](/zh-TW/10-onchain-research/05-whale-tracking/)的展開分析。

## 本節要點

- **沒有"最好的"資料平臺，只有最適合的工具**——TVL 排行用 DefiLlama，深層分析用 Dune，聰明錢追蹤用 Nansen/Arkham
- **Dune 已成研究標準**——200K+ 公開儀表板意味著你 99% 的問題都能找到現成的參考模板
- **跨平臺驗證永遠值得**——任何單一平臺的地址標籤或聚類都可能出錯，必須多個工具交叉確認
- **社交熱度最容易偽造，交易成本最難偽造**——評估專案活躍度時優先看 Gas 消耗量而非粉絲數
- **資料延遲是隱性成本**——Dune 某些鏈的資料滯後 2-4 小時，DEX 交易量排行是即時的，需要根據場景選擇
- **單筆異動不等於趨勢**——鏈上資料是群體行為的反映，一定要看聚合趨勢而非單個事件

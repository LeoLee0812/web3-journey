> **一句話結論：** 雜湊函式是區塊鏈的「指紋機器」，將任意資料壓縮成固定長度的唯一標識；以太坊採用 Keccak-256（抗長度擴充套件攻擊）而比特幣用 SHA-256（硬體最佳化），兩者雖然名字接近，但構造方法和安全特性完全不同，混用會導致地址生成失敗。

## 為什麼手機也能驗證一個 10GB 的大檔案

你是否注意過，從網際網路下載一個 Linux ISO（幾GB 大小）後，往往會看到一串數字或字母的「校驗值」？例如：

```
SHA-256: d9b3e5c2a1f7...（64 個十六進位制字元）
```

只需對比這個字串，就能瞬間檢驗檔案是否被篡改或損壞。這背後的魔法就是**雜湊函式**。

區塊鏈用同樣的原理：每個區塊、每筆交易、每個帳戶都用雜湊函式生成一個「指紋」。這個指紋有三個神奇特性：
1. **確定性**：同樣的輸入永遠生成同樣的輸出
2. **單向性**：不可能從輸出反推輸入
3. **雪崩效應**：輸入改一個字元，輸出也會徹底改變

但這還不夠。區塊鏈對雜湊函式有額外的嚴苛要求——特別是**抗碰撞能力**（兩個不同輸入不能生成同樣輸出）和**長度擴充套件攻擊防護**。正因為這些要求，以太坊沒有跟隨比特幣選擇 SHA-256，而是改用 Keccak-256。

**核心差異表：**

| 特性 | SHA-256 | Keccak-256 |
|------|---------|-----------|
| **使用鏈** | 比特幣、BCH 等 | 以太坊及 EVM 相容鏈 |
| **構造方法** | Merkle–Damgård | 海綿（Sponge） |
| **輸出長度** | 固定 256 位 | 靈活（可輸出任意長度） |
| **長度擴充套件攻擊** | 易受影響（需額外防護） | 原生抵抗 |
| **硬體最佳化** | 極優（挖礦友好） | 良好（多硬體支援） |
| **並行處理** | 差 | 支援 |
| **NIST 標準** | SHA-2 家族（2001） | 原始 Keccak（2015 改版為 SHA-3，但以太坊仍用舊版） |

### 為什麼以太坊不用 SHA-256

**長度擴充套件攻擊（Length Extension Attack）**是關鍵。想像一個支付場景：你傳送了一條訊息 `"pay 10 ETH to Alice"`，並用 SHA-256(私鑰 + 訊息) 生成簽名。攻擊者無法改動訊息本身（因為需要私鑰），但在 SHA-256 的 Merkle–Damgård 構造下，**攻擊者可以在不知道私鑰的情況下，計算出 SHA-256(私鑰 + 訊息 + 惡意字尾) 的雜湊值**。這就悄無聲息地改變了交易意圖。

Keccak-256 採用的**海綿構造（Sponge Construction）**天然免疫這類攻擊。此外，Keccak 的原始設計比 SHA-256 更年輕，在密碼分析上也有更多的超前思考。

### 以太坊採用原始 Keccak 的歷史遺留

2015 年，NIST 正式釋出 SHA-3 標準時，對 Keccak 的填充方案（padding）做了輕微調整以提高靈活性。但以太坊在此之前已經採用了原始 Keccak-256，上線後就一直沿用至今。這樣做的好處是保持穩定性；缺點是造成了混淆——有些文件會說以太坊用 SHA-3，但實際是用原始 Keccak，兩者生成的雜湊值完全不同。

## 在以太坊中的三個核心用途

**1. 生成帳戶地址：** 對公鑰呼叫 Keccak-256，再取最後 20 位元組 = 40 個十六進位制字元的以太坊地址

**2. 交易雜湊：** 對整個交易資料（gas price、nonce、to 地址等）呼叫 Keccak-256，得到 txHash，永久記錄在區塊鏈上

**3. 狀態樹節點：** 以太坊的帳戶狀態儲存在 Merkle Patricia 樹中，每個節點的雜湊也是用 Keccak-256 計算，這樣輕節點可以快速驗證任意帳戶餘額

## 🧪 真實案例：地址生成環節的雜湊陷阱

以太坊地址是 Keccak-256 雜湊公鑰後取最後 20 位元組得到的，這個環節本身很穩固——真正的風險點在於**餵給雜湊函式之前的私鑰/公鑰是怎麼生成的**。2022 年 Wintermute 量化做市商用了一個只有 32 位偽隨機種子的虛榮地址生成工具，導致私鑰被暴力列舉、損失 $1.6 億美元，完整案例見[本章第 1 節](/zh-TW/03-cryptography/01-symmetric-vs-asymmetric/)。

這提醒我們：雜湊函式本身（Keccak-256、SHA-256）的單向性、抗碰撞性再強，也保護不了一個從弱熵生成的私鑰——安全鏈條只和最薄弱的一環一樣結實。

## ⚠️ 常見坑與誤區

**坑 1：混淆 Keccak-256 和 SHA3-256**
以太坊官方程式碼中的 `keccak256()` 函式用的是原始 Keccak，不是 NIST 標準化的 SHA3-256。兩者雜湊值完全不同。如果你從其他庫（如 Python 的 hashlib）呼叫 SHA3-256 並試圖匹配以太坊地址生成，會失敗。

**坑 2：在雜湊之前改變資料編碼**
生成地址時，必須對公鑰的**二進位制資料**（20 位元組）呼叫 Keccak-256，而不是對十六進位制字串雜湊。如果誤用了字串編碼，結果完全不同。

**坑 3：硬體錢包的盲簽名**
硬體錢包螢幕顯示「交易雜湊」時，使用者看到的是一個 64 字元的十六進位制串。這個雜湊是對交易資料的 Keccak-256 計算結果，但它只代表「這筆交易的指紋」，無法讓使用者驗證**真實的轉帳目標地址**。攻擊者可能篡改了交易的 to 地址，而雜湊值看起來完全正常。這就是所謂的「盲簽名」風險。

**坑 4：認為雜湊值可以逆向**
有些新手期望能從地址反推公鑰、從公鑰反推私鑰。Keccak-256 的單向性意味著這**在數學上不可能**。這也是為什麼地址洩露不等於私鑰洩露。

## 本節要點

- 雜湊函式的三大性質：確定性、單向性、雪崩效應
- SHA-256（比特幣）vs Keccak-256（以太坊）的核心差異在於**構造方法**（Merkle–Damgård vs 海綿）和**長度擴充套件攻擊防護**
- 以太坊用 Keccak-256 是因為它在多硬體上更均衡，且原生抵抗長度擴充套件攻擊
- 虛榮地址工具必須用加密級強隨機數（≥256 位熵），32 位偽隨機數對現代 GPU 完全無防禦能力
- Keccak-256 ≠ SHA3-256；混用會導致地址生成失敗
- 硬體錢包的盲簽名風險無法完全消除，需要在交易前用區塊瀏覽器的「Decode Input Data」人工驗證

> **一句話結論：** 數字簽名用 ECDSA 演算法證明你擁有私鑰而無需暴露它，交易簽名中甚至隱含了足以恢復公鑰的資訊，讓區塊鏈網路無需顯式收到傳送方地址也能驗證交易合法性。

## 從「確認」按鈕說起

你在 MetaMask 看到轉帳提示，點一下「確認」按鈕。這一刻，錢包做了什麼？

**直觀的理解是錯的：** 不是把私鑰發給網路去驗證。相反，錢包用私鑰對交易資料進行了一次**不可逆的數學變換**——生成一個簽名。這個簽名有三個神奇的性質：

1. **只有你能生成** — 因為只有你知道私鑰
2. **任何人都能驗證** — 只用公鑰就行
3. **改不了** — 篡改交易任何一位元組，簽名都失效

這就是非對稱密碼學最優雅的應用：**數字簽名**。

## 簽名是怎麼生成的

以太坊採用 **ECDSA**（橢圓曲線數字簽名演算法），用 secp256k1 曲線。簽名過程分三步：

**第一步：雜湊交易資料**

你的交易（轉帳 0.5 ETH 給 Alice）包含多個欄位：傳送方、接收方、金額、Gas、Nonce 等。錢包把這些資料拼接並用 Keccak-256 雜湊，得到一個 256 位的數字 `m`（Message Hash）。

**第二步：生成隨機數 k**

這一步容易被忽視，但極其關鍵。簽名演算法**必須**生成一個隨機數 `k`（1 到曲線階數 n 之間）。這個 k 不會出現在最終簽名裡，但它的質量決定了簽名是否安全。

**第三步：運算出簽名 (r, s)**

用橢圓曲線點乘法：

1. 計算 `K = k × G`（k 乘以基點），得到點 (x, y)
2. `r = x mod n`（取 x 座標的模值）
3. `s = k^(-1) × (m + r × 私鑰) mod n`

最終簽名就是兩個數字：`(r, s)`。

## 為什麼這個簽名不可偽造

假設攻擊者看到了你的簽名 `(r, s)` 和交易雜湊 `m`，想偽造一個新交易（給自己轉帳 100 ETH）。新交易的雜湊 `m'` 完全不同。

現在攻擊者需要為這個 `m'` 生成一個有效的 `(r', s')`。問題是：`s` 的公式裡包含 **私鑰**，而私鑰無法從 `r、s、m` 這些公開資訊反推出來（這就是橢圓曲線離散對數問題的難度保證）。

除非攻擊者知道私鑰，否則無法生成有效簽名。

## 以太坊的巧妙之處：從簽名恢復公鑰

Bitcoin 交易必須顯式包含傳送方的公鑰。但以太坊不這樣做——它依靠一個數學技巧：**從簽名本身恢復公鑰**。

這裡的魔法在於：給定 `m、r、s` 和一個恢復 ID（recovery ID，0-3 之間），你能反推出公鑰。恢復 ID 只需 2 位，而以太坊把它編碼進交易的 `v` 欄位（簽名中的第三個分量）。

**實際流程：**

1. 節點收到交易 + 簽名 `(r, s, v)`
2. 用 `(m, r, s, v)` 恢復公鑰 `K`
3. 用 Keccak-256 雜湊公鑰，取最後 20 位元組，得到地址
4. 檢查這個地址是否與交易聲稱的傳送方一致
5. 如果一致，說明簽名確實由持有該地址私鑰的人生成

這樣做的好處：**交易資料更緊湊**（不用存放公鑰），**網路驗證自動化**（無需人工指定傳送方）。

<Aside type="tip">
以太坊採用原始 Keccak-256，不是 NIST 標準的 SHA-3。這個歷史遺留至今仍在使用，原因是 Keccak-256 在海綿構造上有更強的抗長度擴充套件攻擊能力。
</Aside>

## ⚠️ 常見坑與安全隱患

### 隨機數 k 的質量是絕對的紅線

如果 `k` 固定、可預測或部分洩露，私鑰可以被完全恢復。這不是理論漏洞——**2013 年，比特幣錢包因為 Android 隨機數生成器的 Bug 導致數百萬美元被盜**。

具體地，如果攻擊者知道兩個簽名用了相關的 `k1` 和 `k2`（如 `k2 = 2 × k1`），可以通過聯立方程組恢復私鑰。

**現代錢包如何防護：** 使用加密級偽隨機數生成器（如 Web Crypto API 的 `crypto.getRandomValues()`），而非通用 PRNG。

### 盲簽名陷阱

硬體錢包（Ledger、Trezor）螢幕極小，無法顯示完整的交易資料。大多數情況下只能顯示交易雜湊。這意味著：

即使你看到螢幕顯示"確認轉帳 1 ETH"，實際簽署的交易可能是一份授權無限額度的智能合約呼叫（`setApprovalForAll`）。你的錢包已簽署，但目標完全不同。

**Ledger 的對策：** 推出"Clear Sign Everything"計劃，對常見合約進行硬編碼解析。Trezor 則整合 Blockaid 服務進行交易模擬。但根本的風險（簽名方無法完全驗證意圖）仍未消除。

### EIP-55 地址校驗被忽視

以太坊地址是 40 個十六進位制字元，一個字元改錯就會轉到完全不同的地址。EIP-55 用 Keccak-256 雜湊決定大小寫來提供校驗，但許多錢包並不強制檢查大小寫。

**最安全的做法：** 複製貼上地址時保留原有大小寫，或在粘貼後用區塊瀏覽器驗證。

### 交易重放攻擊

簽名只對特定交易和鏈有效。但如果兩條鏈都用 secp256k1 曲線（如以太坊和 ETC），同一個簽名可能在兩條鏈上都有效。

現代鏈通過在雜湊資料中加入 **Chain ID** 來防止這個問題（EIP-155）。

## 本節要點

- ECDSA 簽名由 `(r, s)` 兩個數字組成，需要一個高質量的隨機數 `k` 保證安全
- 簽名證明了你擁有私鑰，而無需暴露私鑰本身
- 以太坊可以從簽名恢復公鑰，因此交易無需顯式包含傳送方地址
- 隨機數 `k` 的質量是絕對的紅線；弱熵導致私鑰洩露的案例已屢見不鮮
- 硬體錢包的盲簽名陷阱依然存在，再好的工具也無法防止使用者被誘導簽署惡意交易
- 在多鏈生態中，EIP-155 Chain ID 防止簽名被重放到其他鏈

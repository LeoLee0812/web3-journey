> **一句話結論：** 智能合約就是一個自動售貨機——接收交易（投幣），檢查條件（商品庫存），執行邏輯（出貨），改寫狀態（庫存減少），但它永遠無法主動向外界說"買我的商品"。

## 為什麼要講這個

![街邊一排自動售貨機](/images/05-ethereum-smart-contracts/03-what-is-contract.jpg)

*圖注：智能合約就像這些售貨機——不投幣就不會出貨，永遠被動等待指令 · 圖片：Pexels / Huu Huynh*

你可能聽過"智能合約自動執行"、"無需信任"這樣的說法，但這些詞很容易讓人想像錯誤。很多人以為智能合約是一個主動的、會自己做決策的"智慧助手"，其實恰恰相反——合約是完全被動的。

想像你在便利店買水。店員的流程是：看到你拿起水瓶 → 掃描商品碼 → 檢查庫存 → 收錢 → 給你結帳收據。這是**有感知、會主動響應**的行為。但自動售貨機呢？它只能等你投幣，然後機械地執行預設的程式。如果沒有人按按鈕，它就一動不動。

以太坊上的智能合約正是這個原理。沒有"聰明"可言，它的"智慧"不過是程式碼的自動執行和不可篡改。理解這一點，你才能真正把握合約能做什麼、不能做什麼。

## 核心機制拆解

### 三大構成與被動本質

一個完整的智能合約包含三個不可分割的部分：

| 構成部分 | 實際內容 | 作用 |
|---------|--------|------|
| **程式碼** | Solidity編寫，編譯為EVM位元組碼 | 決定執行邏輯（怎麼做） |
| **儲存** | 鏈上持久化的鍵值對資料庫 | 記錄當前狀態（有什麼） |
| **餘額** | 該合約名下的ETH，以wei計（1 ETH = 10^18 wei） | 合約自身資產（1 wei是最小單位） |

程式碼規定兌換規則，儲存記錄使用者帳戶餘額，餘額存著合約賺到的手續費。這三部分缺一不可。

合約本身**沒有時鐘、沒有眼睛、沒有意志**。它不會主動檢查價格、不會自動觸發行為、也無法發起網路請求。合約**只能被呼叫**——必須有人（或機器人）傳送交易，合約才會執行：

### 從投幣到出貨

當你在錢包點選"傳送"時，實際上是向EVM說："執行合約X上的函式Y"。EVM的執行流程是確定性的：

1. **驗證簽名**：確保你的私鑰簽過這筆交易
2. **預扣Gas費**：計算會消耗多少計算資源
3. **執行位元組碼**：逐條執行合約指令
4. **改寫儲存**：修改帳戶餘額、代幣數量等狀態
5. **產生收據**：記錄Gas消耗和發生的事件

整個過程**確定性、透明、不可逆**。無論誰執行，結果都相同——這就是"智慧"的含義，不需要第三方背書。

### 部署即永久寫入

你編譯好的Solidity程式碼要部署到鏈上。部署就是傳送一筆特殊交易，資料欄位填入位元組碼和初始引數。EVM執行時：

1. 執行建構函式（`constructor`），初始化狀態變數
2. 計算合約地址（由部署者地址和nonce組合生成，或CREATE2雜湊）
3. 永久儲存程式碼到這個地址上

**一旦部署，程式碼就無法改變**（除非用代理模式）。這就是為什麼合約審計極其重要——一行程式碼的漏洞可能伴隨合約一生。

## 🧪 真實案例：The DAO 重入漏洞

2016年6月，以太坊最大眾籌專案The DAO被駭客利用**重入漏洞**盜走360萬個ETH。駭客的手段很巧妙：

合約程式碼是"檢查餘額 → 轉帳 → 更新余額"。但在轉帳那一刻，駭客觸發合約的回撥函式（`fallback`），在餘額還沒被更新前再次進入合約，重複提取。售貨機程式有漏洞，就出貨了不該出的商品。

修復其實很簡單——改為"檢查餘額 → 更新余額 → 轉帳"，這樣駭客再進來時餘額已是零。但**合約無法改**，只能整個以太坊硬分叉回滾，引發巨大爭議並分裂出Ethereum Classic。這完美說明了程式碼即法律的無情和合約的永久性。

## ⚠️ 常見坑與誤區

1. **自動執行≠主動執行**  
   合約永遠被動，沒人調它就永遠睡覺。必須有機器人或預言機定時傳送交易才能觸發。

2. **"智慧"這個詞易誤導**  
   合約不會學習、不會最佳化、不會自適應。唯一的優勢是程式碼自動執行和完全透明。

3. **交易回滾仍要付Gas費**  
   執行過程中如果條件不滿足（餘額不足等），整個交易回滾如同未發生。但你已被扣Gas費（計算資源消耗是真實的）。

4. **程式碼一旦部署就永久寫死**  
   任何bug都無法修復，除非當初設計了升級機制。這是不可篡改的代價。

5. **資料都是公開可讀的**  
   標記為`private`的狀態變數只是編譯層限制，無法真正隱藏資料——所有內容都在區塊鏈上。

## 本節要點

- 智能合約 = 自動售貨機，被動響應、按程式執行、永不主動
- 由程式碼（邏輯）、儲存（狀態）、餘額（資產）三部分組成
- 交易觸發執行流程：驗證簽名 → 扣Gas → 執行程式碼 → 改寫狀態 → 記錄區塊
- 部署後代碼永久寫入，無法修改（除非事先設計升級機制）
- 安全性完全取決於程式碼嚴謹性，一行漏洞可能伴隨合約終身

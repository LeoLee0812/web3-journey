> **一句话结论：** 数字签名用 ECDSA 算法证明你拥有私钥而无需暴露它，交易签名中甚至隐含了足以恢复公钥的信息，让区块链网络无需显式收到发送方地址也能验证交易合法性。

## 从「确认」按钮说起

你在 MetaMask 看到转账提示，点一下「确认」按钮。这一刻，钱包做了什么？

**直观的理解是错的：** 不是把私钥发给网络去验证。相反，钱包用私钥对交易数据进行了一次**不可逆的数学变换**——生成一个签名。这个签名有三个神奇的性质：

1. **只有你能生成** — 因为只有你知道私钥
2. **任何人都能验证** — 只用公钥就行
3. **改不了** — 篡改交易任何一字节，签名都失效

这就是非对称密码学最优雅的应用：**数字签名**。

## 签名是怎么生成的

以太坊采用 **ECDSA**（椭圆曲线数字签名算法），用 secp256k1 曲线。签名过程分三步：

**第一步：哈希交易数据**

你的交易（转账 0.5 ETH 给 Alice）包含多个字段：发送方、接收方、金额、Gas、Nonce 等。钱包把这些数据拼接并用 Keccak-256 哈希，得到一个 256 位的数字 `m`（Message Hash）。

**第二步：生成随机数 k**

这一步容易被忽视，但极其关键。签名算法**必须**生成一个随机数 `k`（1 到曲线阶数 n 之间）。这个 k 不会出现在最终签名里，但它的质量决定了签名是否安全。

**第三步：运算出签名 (r, s)**

用椭圆曲线点乘法：

1. 计算 `K = k × G`（k 乘以基点），得到点 (x, y)
2. `r = x mod n`（取 x 坐标的模值）
3. `s = k^(-1) × (m + r × 私钥) mod n`

最终签名就是两个数字：`(r, s)`。

## 为什么这个签名不可伪造

假设攻击者看到了你的签名 `(r, s)` 和交易哈希 `m`，想伪造一个新交易（给自己转账 100 ETH）。新交易的哈希 `m'` 完全不同。

现在攻击者需要为这个 `m'` 生成一个有效的 `(r', s')`。问题是：`s` 的公式里包含 **私钥**，而私钥无法从 `r、s、m` 这些公开信息反推出来（这就是椭圆曲线离散对数问题的难度保证）。

除非攻击者知道私钥，否则无法生成有效签名。

## 以太坊的巧妙之处：从签名恢复公钥

Bitcoin 交易必须显式包含发送方的公钥。但以太坊不这样做——它依靠一个数学技巧：**从签名本身恢复公钥**。

这里的魔法在于：给定 `m、r、s` 和一个恢复 ID（recovery ID，0-3 之间），你能反推出公钥。恢复 ID 只需 2 位，而以太坊把它编码进交易的 `v` 字段（签名中的第三个分量）。

**实际流程：**

1. 节点收到交易 + 签名 `(r, s, v)`
2. 用 `(m, r, s, v)` 恢复公钥 `K`
3. 用 Keccak-256 哈希公钥，取最后 20 字节，得到地址
4. 检查这个地址是否与交易声称的发送方一致
5. 如果一致，说明签名确实由持有该地址私钥的人生成

这样做的好处：**交易数据更紧凑**（不用存放公钥），**网络验证自动化**（无需人工指定发送方）。

<Aside type="tip">
以太坊采用原始 Keccak-256，不是 NIST 标准的 SHA-3。这个历史遗留至今仍在使用，原因是 Keccak-256 在海绵构造上有更强的抗长度扩展攻击能力。
</Aside>

## ⚠️ 常见坑与安全隐患

### 随机数 k 的质量是绝对的红线

如果 `k` 固定、可预测或部分泄露，私钥可以被完全恢复。这不是理论漏洞——**2013 年，比特币钱包因为 Android 随机数生成器的 Bug 导致数百万美元被盗**。

具体地，如果攻击者知道两个签名用了相关的 `k1` 和 `k2`（如 `k2 = 2 × k1`），可以通过联立方程组恢复私钥。

**现代钱包如何防护：** 使用加密级伪随机数生成器（如 Web Crypto API 的 `crypto.getRandomValues()`），而非通用 PRNG。

### 盲签名陷阱

硬件钱包（Ledger、Trezor）屏幕极小，无法显示完整的交易数据。大多数情况下只能显示交易哈希。这意味着：

即使你看到屏幕显示"确认转账 1 ETH"，实际签署的交易可能是一份授权无限额度的智能合约调用（`setApprovalForAll`）。你的钱包已签署，但目标完全不同。

**Ledger 的对策：** 推出"Clear Sign Everything"计划，对常见合约进行硬编码解析。Trezor 则集成 Blockaid 服务进行交易模拟。但根本的风险（签名方无法完全验证意图）仍未消除。

### EIP-55 地址校验被忽视

以太坊地址是 40 个十六进制字符，一个字符改错就会转到完全不同的地址。EIP-55 用 Keccak-256 哈希决定大小写来提供校验，但许多钱包并不强制检查大小写。

**最安全的做法：** 复制粘贴地址时保留原有大小写，或在粘贴后用区块浏览器验证。

### 交易重放攻击

签名只对特定交易和链有效。但如果两条链都用 secp256k1 曲线（如以太坊和 ETC），同一个签名可能在两条链上都有效。

现代链通过在哈希数据中加入 **Chain ID** 来防止这个问题（EIP-155）。

## 本节要点

- ECDSA 签名由 `(r, s)` 两个数字组成，需要一个高质量的随机数 `k` 保证安全
- 签名证明了你拥有私钥，而无需暴露私钥本身
- 以太坊可以从签名恢复公钥，因此交易无需显式包含发送方地址
- 随机数 `k` 的质量是绝对的红线；弱熵导致私钥泄露的案例已屡见不鲜
- 硬件钱包的盲签名陷阱依然存在，再好的工具也无法防止用户被诱导签署恶意交易
- 在多链生态中，EIP-155 Chain ID 防止签名被重放到其他链

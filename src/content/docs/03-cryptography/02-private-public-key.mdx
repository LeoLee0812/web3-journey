> **一句话结论：** 私钥是 256 位随机数，通过椭圆曲线点乘生成公钥，再通过 Keccak-256 哈希取最后 20 字节得到地址——整个链条是单向的，不可逆推。

## 你的房子、钥匙和门牌号

想象你的房钥匙（私钥）可以公开展示，但任何人都无法从钥匙推出门牌号（地址），也无法从门牌号反推钥匙的样子。这就是非对称加密的核心思想。

以太坊选择的方案是：钥匙是**随机生成的 256 位数字**，而不是物理物体。通过椭圆曲线和哈希函数，这个数字最终转化为一个 42 字符的地址——整个链条单向不可逆。

## 私钥：一切的开始

**私钥是什么？** 一个 256 位的二进制数，通常表示为 64 个十六进制字符。例如 `0xabc...def` 这样的形式。

256 位能表达多少个不同的私钥？理论上是 2^256 ≈ 10^77 个。这个数字大到什么程度？**全世界所有沙粒的数量约 10^24，而 10^77 比这大得多得多。** 这意味着随机生成两个相同的私钥的概率低到可以忽略。

**生成方式的致命要点：必须用密码学级别的随机数生成器（CSPRNG）。** 不是你操作系统的普通随机数，不是 Mersenne Twister，必须是经过密码学验证的真随机源（如操作系统的 `/dev/urandom`、浏览器的 `crypto.getRandomValues()`）。

为什么？因为如果熵不足——比如只用 32 位种子生成私钥——攻击者可以在几小时内用 GPU 暴力枚举所有 2^32（约 40 亿）种可能的私钥，进而计算出对应的地址，找到你的资金。这不是理论威胁，而是真实发生过的事故，详见[本章第 1 节](/03-cryptography/01-symmetric-vs-asymmetric/)的 Wintermute 案例。

## 公钥：椭圆曲线上的魔法

有了私钥之后，下一步是生成公钥。这不是简单的数学运算（如乘以一个常数），而是用 **ECDSA（椭圆曲线数字签名算法）** 上的一条特定曲线：**secp256k1**。

曲线方程是：
```text
y² = x³ + 7 mod p
```

这条曲线定义了一个数学群，群中有大约 2^256 个点。私钥就是对这个群的生成元点（叫 G 点）进行「乘法」运算的次数：

```text
公钥 = 私钥 × G
```

这里的「乘法」不是普通乘法，而是椭圆曲线上的点加法重复进行——数学家称之为「标量乘法」。计算过程如下：

1. 取私钥的二进制表示
2. 从 G 点开始，根据私钥的每一位，做点加法或倍增
3. 最终得到一个坐标对 (x, y)，这就是公钥

**公钥的大小**：通常 x 和 y 各占 256 位，合计 512 位，用 130 个十六进制字符表示（包括前缀 `04`）。未压缩形式下：`04 + 64个字符(x坐标) + 64个字符(y坐标)`。

**这里的关键性质**：椭圆曲线点乘是**单向函数**。给定公钥无法推回私钥，除非能解决「椭圆曲线离散对数问题」——这是目前认为没有有效算法的硬问题（除非量子计算机出现）。这就是为什么你可以安全地把公钥分享出去。

## 地址：哈希的最后一步

以太坊的地址生成步骤：

1. 取公钥的 512 位（x, y 坐标）
2. 对这 64 字节的数据用 **Keccak-256** 哈希（注意：是 Keccak-256，不是 SHA-256，也不是 NIST 的 SHA-3。以太坊采用的是原始 Keccak 算法）
3. 取哈希结果的**最后 20 字节**（160 位）
4. 前缀加 `0x`，得到 42 字符的地址

**关键数据对照表**：

| 环节 | 大小 | 格式 |
|------|------|------|
| 私钥 | 256 位 / 32 字节 | 64 个十六进制字符 |
| 公钥（未压缩） | 512 位 / 64 字节 | `04` + 128 个十六进制字符 |
| 地址 | 160 位 / 20 字节 | `0x` + 40 个十六进制字符 |

**为什么是最后 20 字节？** 这是设计权衡——足够安全，又不会过度增加交易成本。

**三者的关键关系**：
- 从私钥 → 公钥：**不可逆**（离散对数问题）
- 从公钥 → 地址：**不可逆**（哈希函数的单向性）
- 从地址 → 公钥：**不可逆**（哈希完全性）

这意味着，即使攻击者拿到你的以太坊地址，也无法推出你的公钥或私钥。地址本质上是一个**不可逆的指纹**。

## 🧪 看看推导过程

可以用 Ian Coleman 的 BIP-39 生成器（https://iancoleman.io/bip39/）看到这个过程：输入一个私钥 → 自动生成公钥 → 生成对应的以太坊地址。试着改动私钥的一位，地址会完全不同，说明链条是**确定但敏感**的。

**重要警告**：仅用于学习。真实私钥不要在浏览器中输入，使用硬件钱包（Ledger、Trezor）是正确做法。

## ⚠️ 常见坑与误区

### 坑 1：虚荣地址与熵陷阱

生成一个地址前缀为 `0x000000` 的虚荣地址看起来很酷，但代价巨大。为了生成这样的地址，钱包需要反复尝试新的私钥，直到对应地址的前缀满足要求；如果生成工具用了弱随机数生成器，就在严重削弱熵——真实案例见[本章第 1 节](/03-cryptography/01-symmetric-vs-asymmetric/)。

**预防**：放弃虚荣地址，用真正的 CSPRNG 生成的普通地址。地址的安全性远比视觉效果重要。

### 坑 2：公钥泄露与地址关联

如果你在某笔以太坊交易中使用过某个地址**发送**（而不仅是接收），网络节点可以从签名中恢复你的公钥。恢复公钥后，任何人都能计算出你的地址（通过 Keccak-256 哈希），并追踪你的所有资金流向。

**为什么这是个问题？** 比如你用某个地址在 DEX 上交易，然后想保持隐私。太迟了——你的公钥已经链上公开，地址与身份的关联无法打破。

**预防**：考虑隐私币（如 Monero）或混币服务，但不是以太坊地址层面的解决方案。更实用的做法是**用不同地址进行不同用途**，避免资金流向暴露。

## 本节要点

- 私钥必须用**密码学级随机数生成器**生成，弱熵导致被穷举（Wintermute 教训）。
- 公钥通过 **secp256k1 椭圆曲线**从私钥推导，单向不可逆。
- 地址是公钥 **Keccak-256 哈希的最后 20 字节**，无法从地址反推公钥或私钥。
- 虚荣地址生成会削弱熵；发送交易时公钥会链上公开，需用多地址或隐私手段保护。
